## 当前 Mac 环境与 GPU / NPU / ARM 验证边界

- 当前开发机器为 Mac，没有可用于 CUDA 的 NVIDIA GPU。将本机作为资料生成、CPU 参考实现和可行静态检查环境；GPU 执行以兼容的 Linux NVIDIA GPU / Jetson 目标设备为准。
- 硬件缺失只限制本机验证范围，不改变主题轮换或内容深度。不得跳过 CUDA、TensorRT、PTX / CUTLASS、GPU 访存优化、GPU 体系结构，也不得将这些主题替换成纯 CPU 或 Metal 练习。
- 每个涉及 GPU 的练习仍必须包含完整目标代码、构建配置、输入生成或最小数据说明、依赖与兼容性要求、目标设备编译运行命令、正确性标准、性能分析命令和待记录指标。主练习保持一个核心概念、一个编码练习、一个自测问题；此外每天交付下文规定的量化方法源码讲解与完整使用示例。
- README 的编译运行与实际运行结果应明确区分“Mac 本机可验证部分”和“Linux NVIDIA GPU / Jetson 目标设备待验证部分”。可移植 CPU 参考或数据检查属于同一练习的辅助验证，不能替代 GPU 实现与验收。
- 没有目标设备时明确标记 GPU 编译、执行、精度和性能中哪些未验证，并说明缺少的工具或数据。不得用 CPU 性能、理论推算或模拟结果冒充 GPU 实测，不得声称 Mac 上运行容器即可获得 CUDA GPU 能力。

- RK3588 NPU / RKNN 主题必须保留 ONNX → RKNN 模型转换与 RK3588 板端推理实现。缺少工具链或板卡时，仍生成完整转换脚本、C++ Runtime 代码、构建配置、可生成的最小 ONNX/输入、校准样本说明和板端命令；不能以 CPU 推理替代 NPU 实现，也不能编造已转换出的 `.rknn` 文件。
- ARM SIMD / NEON 是独立的通用 ARM CPU 优化方向，优先利用当前 Apple Silicon Mac 的 arm64 环境实际编译、运行、查看生成指令和测量性能，无需绑定 RK3588。提供标量参考与真实 NEON intrinsics 实现；仅在该练习明确涉及跨平台移植时，再分别验证 RK3588 或其他 ARM 设备。根据本机或所选目标 CPU 和工具链检查指令扩展，保留尾部处理与必要的标量回退，不默认支持 SVE/SVE2 或所有可选扩展；不同微架构的性能结论不能直接互相外推。
- 对 RKNN 分开记录模型转换、CPU/ONNX 参考、板端 Runtime 推理、精度和性能验证状态；区分 CPU 预处理/后处理时间、主机 Runtime 调用时间、工具实际提供的 NPU 设备时间以及端到端延迟。主机 API 耗时不得直接标成 NPU 内核耗时。

### CUDA GPU 优化交付、ncu 与 PTX / SASS（2026-09-18 用户要求）

- **固定目标（最新要求，优先于其他架构选题建议）**：今天及以后所有 CUDA、PTX、SASS 代码和构建/运行/性能分析命令都针对 NVIDIA Jetson Thor **SM110**。默认 `-arch=sm_110` / `CMAKE_CUDA_ARCHITECTURES=110`，PTX `.target sm_110`，反汇编来自该目标的真实产物。不得默认生成 SM80/SM90/SM100 等其他 GPU 目标，也不得擅自切换 `sm_110a` 或其他专属后缀。记录并核实 Thor 的 CUDA/PTX/JetPack/L4T/驱动/ncu 兼容组合；无法核实时明确待验证。其他架构只用于知识和指令差异对照，不改变代码目标。

- **适用范围**：所有涉及 CUDA GPU 的方向，包括 CUDA Kernel、PTX / CUTLASS、GPU 访存优化、GPU 体系结构，以及涉及 GPU kernel 的 TensorRT/边缘部署内容。每次优先选定一个具体 kernel 深入，记录名称、源码位置、输入 Shape、dtype、布局和目标 SM；不得只讲抽象优化口号。
- **交付必须包含优化后的完整实现**：保留可编译运行的正确性基线与最终优化版，清楚标出默认/最终使用哪个 kernel；不能只交付原版代码和“可以优化”的建议。说明“基线 → 瓶颈假设/证据 → 代码改动 → 正确性与性能复测 → 取舍”的完整过程。无 GPU 时照样交付优化实现，但标为“优化候选实现、收益未验证”；不能把使用新指令自动等同于变快。实测优化回退时保留结果并解释最终选择，不强称更优。
- **保持公平对照**：比较版本使用相同 Shape、输入、精度容限、数学语义、计时边界和预热/采样条件。区分优化实际减少的数据搬运、指令、同步、分配或启动次数，以及可能增加的寄存器、shared memory 和调度成本。不能用更改分组语义、减少输出、降低必要精度或删除同步冒充收益。保留一个 20–30 分钟编码练习，将同一 kernel 的优化作为该练习，不额外增加第二个任务。
- **每次提供可操作的 Nsight Compute（ncu）教程**：给出版本检查、section/metric 查询、按 kernel 名称与特定 launch 过滤、预热与采样、导出/打开 .ncu-rep，以及源代码/PTX/SASS 关联步骤。依据当次安装版本与目标架构确认可用 section/metric；至少说明吞吐/带宽、访存事务与合并、寄存器/shared/occupancy、warp 调度与 stall 中哪些指标回答本次瓶颈假设。不只给一条 ncu 命令或堆砌指标；说明看到什么证据才支持哪种改动，权限/计数器不可用时如实记录。Profiler replay/cache 控制会改变测试条件，优化收益以未附加 profiler 的基准为准。
- **PTX / SASS 交付与逐段说明**：尽可能保存该 kernel 的真实 PTX 与 SASS 文本，附 CUDA/ptxas 版本、目标 SM、编译参数、提取命令（nvcc、cuobjdump 或 nvdisasm）及源码行/指令地址对应关系。区分 PTX 虚拟 ISA 与 SASS 机器 ISA，不能把 PTX 当作最终机器指令。无工具链时提供真实手写 inline PTX、完整生成/反汇编命令与待验证清单；示意片段必须注明示意，严禁伪造“实际编译生成的 SASS”。大型二进制报告放在忽略的 build/ 中，只提交适量文本与必要源码片段。
- **解释哪些指令/依赖可能耗时长**：围绕实际 kernel 标出访存、同步、依赖链、特殊函数、矩阵运算等相关指令段，结合 ncu 源码/SASS 视图和计数器说明热点及原因。明确区分单指令延迟、发射吞吐、依赖等待、缓存未命中、执行次数和 warp stall；被采样到停顿的消费者指令不一定是根因。没有实测或明确的目标架构一手依据时，只能称潜在热点，不捏造周期数，不给跨架构通用的“最慢指令排行榜”。
- **每次 GPU 内容都包含以 Thor SM110 为锚点的架构与特色指令对照**：结合本次 kernel 固定分析 Thor SM110，与至少一个其他架构比较，并在连续 GPU 练习之间轮换对照架构或 Thor 指令特性，记录到索引或 memory。覆盖该架构新增/强化的指令及执行机制、适合的工作负载、准确的计算能力/目标后缀、最低工具链与 dtype/布局/同步约束；区分某代新引入、后续沿用和真正架构专属，不能把沿用指令称为某代独有。选题可涉及 Volta/Turing/Ampere/Ada/Hopper/Blackwell，但每项支持条件须先查对应 NVIDIA PTX ISA、tuning guide、产品文档与实际源码；不同产品 SM、架构专属 a/f 特性、Jetson 与桌面/数据中心不能泛化。说明本 kernel 是否真正利用该特性，未使用则解释原因，不为展示新指令强行改写。
- 将优化方案、ncu、指令解析和架构对照放入既有 README 的“编码练习 / 性能分析 / 工程注意事项”等章节，必要时链接专门说明文件；保持既定一级/二级标题顺序、450–700 字概念回顾、一个自测及现有真实性要求。网络或硬件不足时保留失败证据与待核实项，不降低代码交付要求，不假称已经验证。

### 量化 GEMM（第 12 个独立方向，2026-09-18 新增）

- 新增独立轮转方向“量化 GEMM”，位于 PTX / CUTLASS 之后、GPU 访存优化之前。所有 CUDA/PTX/SASS 继续固定 Thor SM110，不因本机缺硬件变成纯理论主题。
- 必须围绕真实矩阵乘 `Y=A×W` 实现与比较 W4A4、W4A16、W8A8、W8A16；后续可在核实支持后扩展格式。明确 W/A 表示权重/激活、INT4/INT8 与 FP4/FP8 的区别，A16 的 FP16/BF16 选择、布局、scale 粒度、分组、零点、舍入、饱和和累加精度。不能把float数组或只做fake quant冒充真实4-bit打包/低精度执行，也不能把标量整数MAC声称为Tensor Core GEMM。
- 朴素 absmax PTQ 只能作为基线。主题必须逐步覆盖并交付可运行的 SmoothQuant、outlier handling、calibration-aware scaling 和 QAT：实现 `A'=A/s, W'=sW` 及未量化等价性检查；实现离群通道混合精度残差/等价真实处理并计算额外成本；使用校准统计与独立调参集选择scale/裁剪，不能用评估集挑参数；QAT必须有实际fake-quant前向、梯度/STE规则、参数更新及训练日志，不能只挂QAT名称。
- 必须比较量化前 FP32 和明确的16位参考、量化后输出，记录 NRMSE/最大绝对误差/余弦、饱和率、分布变化与边界；区分真实模型任务精度和合成单层重建误差。明确训练/校准/调参/评估数据分离，至少包括零值、异常维度或尾块等正确性边界；保留无收益或退化结果，不保证QAT/缩放对所有位宽有效。
- 真实打包低位权重，明确对应矩阵乘路径：整型激活可用INT32累加再按group缩放，A16可解码权重并用选定浮点累加。给出朴素kernel与最终优化kernel、ncu/真实PTX/SASS导出及指令分析，计算权重、激活、scale/零点、离群残差等存储开销。区分离线校准/QAT、在线quantize/pack、kernel、传输与端到端时间；没有Thor实测不得声称压缩比等于提速比。
- 优先实际阅读 mit-han-lab/smoothquant、PyTorch/torchao、NVIDIA/CUTLASS/Model Optimizer 等与当次机制对应的实现并记录精确文件/符号和版本；不能把独立简化实验称为原项目复现。保持每次一个20–30分钟编码练习和一个无答案自测；完整对照框架可预先提供，单次操作只聚焦一个明确设计点，其余作为基线/对照。

### RK3588 NPU / RKNN 与独立 ARM SIMD 方向的选题范围

- **RK3588 NPU / RKNN**：围绕 ONNX 算子与 Shape 支持、模型转换与图优化、预处理一致性、INT8 校准与量化误差定位、输入输出布局/类型/量化参数查询、C++ RKNN Runtime 的资源生命周期、stride 与缓冲区约束、内存绑定/减少复制、多核调度及 CPU–NPU 流水线选一个点深入。具体 API、算子支持、内存一致性和核调度能力以选定 SDK/驱动版本的官方文档与源码为准，不能把候选选题当作所有版本都支持的能力。
- **ARM SIMD / NEON**：以 ggml、ncnn 的 ARM CPU 实现作为优先源码来源，围绕 `arm_neon.h` intrinsics 与 AArch64 生成指令，练习向量加载/存储、交错与重排、扩宽累加、饱和/舍入/窄化、归约、尾部与步长处理、浮点误差及可选 dot-product 扩展。优先从量化块与点积、反量化和累加、小矩阵/矩阵向量计算、张量 stride、packing、归约等机制中选一个点；图像预处理/后处理只是可选场景。每次先核实实际源码，再提炼可在 Mac 本机运行的最小实现，比较标量参考与 SIMD 结果、检查生成指令并分析访存或计算瓶颈。
- NPU 侧优先从 Rockchip 官方 RKNN-Toolkit2、RKNN Model Zoo、RKNPU2 示例提炼问题；SIMD 侧优先从 ggml、ncnn 借鉴，按相关性补充 OpenCV、Arm Compute Library 等成熟项目；仅选 CPU/ARM 路径时，不把 Metal/GPU 后端性能记成 NEON 性能。每次仍需实际阅读并标明来源版本/文件/函数，不能仅挂项目名称。
- 转换工具、板端 Runtime 与内核 NPU 驱动分别记录版本，并核实相互兼容性。区分 RKNN-Toolkit2（转换等工具）、RKNN-Toolkit-Lite2（板端 Python 接口）和 RKNN Runtime（板端 C/C++ 接口）。不默认 Mac 可原生运行 RKNN 转换工具，也不默认 PC 生成模型已经在板端通过精度测试。
- 每次只围绕一个机制设置一个编码练习；NPU 和 SIMD 独立选题，只有确实有帮助时才共享部署背景，不把完整模型转换、量化、流水线和 SIMD 优化全部塞进同一天。
