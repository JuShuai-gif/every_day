## 代码与实际指令

[src/kernels.cpp](src/kernels.cpp)与计时主体独立编译、不启用LTO；关闭自动向量化和循环展开，避免编译器把对照变成另一种实验。[首次真实日志](results/initial.txt)展示：

```asm
; serial循环的实际输出节选
ldr x9, [x0], #8
add x8, x9, x8
subs x1, x1, #1
b.ne LBB0_1
; four循环的实际输出节选
ldp x14, x15, [x12, #-16]
add x8, x14, x8
add x10, x15, x10
ldp x14, x15, [x12], #32
add x11, x14, x11
add x9, x15, x9
```

`LDR`取8字节并后增指针，`ADD x8,...,x8`读取上轮x8，形成循环携带依赖；`SUBS`更新计数与条件标志。四链把累加依赖分在x8/x10/x11/x9，`LDP`每次取两个64位值；最后三个ADD合并。LDP存在不意味着一次周期取完，更不能凭它推算A55/A76速度。这里没有NEON算术，下一节才学习自动向量化。

## 工程深入：把微基准结论变成可审查的优化结论

**工作目标**：面对“归约优化了约2.6倍，能否上线”的评审，先回答统计单位、收益来源、适用负载和剩余风险。`measure`一次测128个调用的总时间，再除128；`report`对101个这样的值排序，取索引50和95。因此日志中的P50/P95是**每批平均单调用时间的分位数**，不是4096元素单次请求延迟分布，更不是相机到结果的E2E P95。批处理降低时钟开销占比，也把短暂抖动摊薄，不能拿它承诺服务尾延迟。

### 逐层解释已有数字

最终Release批均值P50比值是`1.74544/0.663734≈2.630`，只描述本次两条完整实现的对比。four的逻辑读取量每次4096×8=32768字节，以其P50换算为约49.37 GB/s的**逻辑读取速率**，不是内存控制器测到的DRAM带宽。输入在每组计时前刚被CPU写入，同一数组再反复读128次；因此是偏热的重复访问负载。32KiB不能仅凭大小就断言完全驻留L1，更不能把49.37与板卡标称内存带宽直接比较。

两版本同时改变了独立累加链、循环分支频率、LDR/LDP与寄存器使用，现有证据不够分离每项贡献。合理结论是“本次four实现的批均值较低，与依赖链减少等机制相容”，而不是“证明ILP单独快2.63倍”。相同shape/语义保证结果对比公平，单因素归因还需要额外受控变体。硬件计数器也不是自动给出因果：低IPC可能来自依赖、加载、前端或其他等待，需配合具体指令和工作集实验。

假设某完整请求原本70%时间由该热点占据，且它确实能独立加速2.630倍、其他部分不变，模型上的总加速比才是`1/(0.3+0.7/2.630)≈1.766`。70%是假设，不是本机测出的业务占比；流水线重叠、同步、传输和队列改变时更不能直接套这个串行公式。这是评估优化优先级的预算方法，不是E2E结果。

### Linux板端的工具入口与计量边界

以下是目标Linux上的预检/粗粒度观察，Mac未执行。需已有perf、taskset、匹配权限与目标C++工具链。先运行本课run.sh完成正确性/构建，再在仓库根目录执行；不要把编译、Sanitizer和打印汇编包进内核性能采集：

```sh
perf --version
perf list
cat /proc/sys/kernel/perf_event_paranoid
: "${CPU_ID:?Select an actual CPU after inspecting topology}"
# 先确认这些事件在该目标可用；不可用要记录原始错误，不能当0。
taskset -c "$CPU_ID" perf stat -r 5 \
  -e task-clock,context-switches,cpu-migrations \
  -- systems_practice/arm/2026-09-29/build/bench
```

这条perf命令包住整个bench进程，混合了两版本、正确性检查、输入生成和报告；它只能粗看进程CPU时间/调度，**不能**把总计数当作serial或four单独的指令/周期。若要按内核归因，先实现单版本、足够长且隔离检查/生成的测量入口，再选择目标实际支持的cycles/instructions/cache事件并检查事件运行比例。该细粒度入口本课未交付，因此未提供假装可用的`--kernel`参数，也不声称已经取得每核PMU结果。

`perf stat -r`报告跨进程运行的平均与标准差，不是本程序的P95。先读perf list再选事件；权限不足保留错误，不自动修改系统策略。2026-09-29实际阅读[perf stat上游手册](https://man7.org/linux/man-pages/man1/perf-stat.1.html)的-e/-r与计数输出，及[Linux perf权限说明](https://www.kernel.org/doc/html/latest/admin-guide/perf-security.html)。
