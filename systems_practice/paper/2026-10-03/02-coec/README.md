# COEC: Calibrated Orthogonal-Equivalence Compensation for Structured Pruning of Large Language Models

Peiqi Yu、Nam Ling、Wei Wang、Wei Jiang；[arXiv:2608.21142v1](https://arxiv.org/abs/2608.21142v1)，首次2026-08-21，v1预印本，未核实同行评审。2026-10-03读[一手正文](https://arxiv.org/html/2608.21142v1)第3节框架、4.1/4.2、Algorithm1、第5.1–5.3实验。作者仓库未查到可核验实现，不声称全算法开源。

## 问题与核心机制

结构化删减后仅保留子矩阵，单侧补偿自由度受限。COEC考虑`W̃ = QL Wkeep QR`，用校准激活的Gram加权输出误差，并在约化Stiefel几何上求解；包含GCV、Gram tempering及层间对齐，不是任意乘两个矩阵。正交变换保持奇异值/范数，因此可以重新定向，不能凭空恢复被剪掉的任意谱信息。

作者30% Wanda-sp的Qwen2.5-32B实验中PPL13.90→9.64，校准使用128条WikiText2样本；这是作者模型/实验设置的结果，不是本机复现。也非所有指标全面领先：Qwen2.5-14B的RCPU对照准确率可领先约0.7点，尽管COEC PPL更低。部署收益还依赖删后形状、算子和补偿合并成本。

## 独立可运行例子

```sh
sh systems_practice/paper/2026-10-03/02-coec/run.sh
```

Python3标准库，保留矩阵diag(2,0.5)，构造目标`R(0.4) Wkeep R(-0.6)`，二维角度格点搜索单侧/双侧。校准12、验证10、测试20个独立样本；训练自由度在校准上拟合，验证决定采用哪类候选，测试仅报告。无梯度训练、无真实结构化剪枝、无GCV/Stiefel全算法，不能将此当原生API。

[真实输出](results/cpu.txt)：单侧测试误差0.3094597785，双侧0，找到角度0.4/-0.6，范数平方4.25保持。目标恰好在搜索网格且由同一双侧族构造，因此零误差是教学构造，不证明一般剪枝可无损。另构造谱尺度不匹配，范数距离平方下界0.960063796，说明纯旋转无法解决所有损伤；没有硬件加速/存储压缩测量。

## 复现与故障边界

全论文复现难：需取得作者源码/许可、精确剪枝索引和数据预处理，准备已有Qwen模型、WikiText2样本，再逐层实现校准Gram、约化求解与对齐，分别测PPL/任务指标和导出后推理；当前无模型或设备，不自动下载，显存/耗时不估为事实。若迁移CUDA，仅在Thor SM110构建/验收。

故障一：校准Gram病态→补偿方向不稳、验证误差增大→检查谱及正则策略→按验证集选择，不能把训练损失下降直接当泛化。故障二：将显式QL/QR留在线上→增加额外矩阵乘抵消剪枝收益→检查可合并边界及端到端时间→以导出结构验收或回滚。故障三：删掉重要谱能量后试图只旋转补救→存在不可消除残差→比较范数/谱及本例下界→调整保留结构而非无限搜索角度。
