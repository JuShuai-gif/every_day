# P4Q: Co-designing Token Pruning and Quantization for Vision-Language Model Acceleration

## 文献与实际阅读

Haizhao Jing、Zhenhao Shang、Haokui Zhang、Rong Xiao、Peng Wang；[arXiv:2609.34867v1](https://arxiv.org/abs/2609.34867)，首发与版本2026-09-28，预印本，未核实会议接收。2026-10-13实际读[全文](https://arxiv.org/html/2609.34867v1)3.1–3.3公式1–5、4.1实验设置及表1/表2。论文采用arXiv non-exclusive分发许可。正文/标题+作者GitHub检索未核实官方实现，不提供猜测的原生API，也不把第三方搜索摘要算源码阅读。

## 问题、机制与作者结果

量化会扰动Top-K边界，剪枝又改变校准分布。P4Q先对projector特征副本fake-quant，再按query相关、视觉saliency、最大最小多样性分配预算；选中索引对应的原FP16特征送下游。校准采用同一选择器与token预算，逐block重建。作者表1：LLaVA-NeXT-7B保留320/2880视觉token、W4A4，在单RTX4090、batch1的八基准平均端到端2.80×、峰值内存51.3%，性能保留95.5%。这些是作者报告，不是Thor实测或每个任务都无损。[方法与表1](https://arxiv.org/html/2609.34867v1#S4.T1)。

## 独立小例：保留反例而非预设改善

```sh
sh systems_practice/paper/2026-10-13/02-p4q/run.sh
```

[example.py](example.py)仅标准库，合成每样本10×4特征，保留5个；三步选择分配约30/20/剩余多样性，语义query固定，saliency是人工输入而非视觉塔。QDQ仅作用评分副本、转发原数据，排序恢复原位置。校准seed41、评估seed42、偏移seed43；两组独立裁剪范围网格搜索分别使用dense/retained样本，固定选择器后只评估，不反向调整。

它**不实现**作者完整block重建、对角scale学习、真实INT4打包、LLM注意力或任务数据，训练更新次数0。QDQ不是低位kernel性能。示例的MSE只是特征重建，不能称作者模型指标。

[实际输出](results/cpu.json)：16个评估样本中15个保留集合随量化改变；正常留出MSE dense校准0.2449105、retained校准0.2721191（退化）；分布偏移下分别0.1514811、0.1202804。0/10预算、11预算拒绝、无输入修改检查通过。单次seed结论不能说明哪种策略普遍更优；合成选择器/极小样本正是可能退化的原因，完整解释需要更大独立评估。

## 复现难度与迁移路线

机制例易；完整论文难：原生代码与确切依赖未核实，需要本地LLaVA-NeXT-7B、视觉预处理/位置ID、128校准样本及八任务评估、支持实际部署格式的后端。没有自动安装或下载。先固定FP16前向与token索引，再单独核对选择支持集，最后比较相同输入/预算/精度合同下的部署端到端时间。作者4090仅作为论文历史平台；本项目新增执行固定Thor SM110，后端编译及工具链兼容待验，没有照搬其他SM命令。

## 故障链与验收

故障一：FP16选择指标正常而量化部署掉分→Top-K边界被扰动→记录相同原始token索引的支持集差异→让selector使用目标精度扰动，代价是评分开销，不能把fake-quant副本误送下游。

故障二：校准损失低但上线漂移→校准token预算/分布不同→固定选择器、预算、位置ID和样本划分，比较独立任务输出→重做匹配校准但保留失败结果，不能把评估样本并入校准。

验收：预算0/全部/非法；集合无重复、位置语义不变；评分不篡改原特征；校准/评估分离；记录选择器预处理、kernel与E2E成本；真打包与后端性能另测。

追问：①Top-K为何对小扰动不连续？②评分副本和下游特征为何要分开？③saliency与query信号各自遗漏什么？④预算改变为何影响校准？⑤同分布小样本为何仍可能退化？⑥如何证明加速来自真实执行而非只缩小张量统计？
