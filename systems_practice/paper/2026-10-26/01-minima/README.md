# Minima-KV：全局归一化与混合页面

论文：Sergii Kozyrev、Davyd Maiboroda，[arXiv:2608.23834v1](https://arxiv.org/html/2608.23834v1)，首发/本版本2026-08-24；2026-10-26读取，预印本，未核实同行评审接收。实际阅读§3.1–3.3、§4.1、§6.2–6.3、§8选段和表3，非只读摘要。

## 核心收获与作者证据

近期/锚点页与较旧页用不同精度，旧页仍可访问。各分区先算最大值m、指数和l及归一输出O，再按统一最大值重标定权重后合并。作者报告单次双请求direct canary吞吐比0.9821，说明容量改善并不保证加速；该实验与质量实验配置分开，且dense对照dtype未绑定。[原文§3.3与§6.3](https://arxiv.org/html/2608.23834v1)

本文还发现表3中97.27→93.75与所列−0.9 pp算术不一致，不引用这个差值为可靠精度结论。作者仓库未在一手正文中定位，检索同名GitHub未得到可验证作者实现；不能声称读过作者kernel。具体来源/缺口见[source.json](source.json)。

## 独立现成示例

[example.py](example.py)只演示分区attention合并：`m=max(mj)`，`wj=exp(mj-m)*lj`，`O=sum(wj*Oj)/sum(wj)`。没有实现FP8/TQ3、页表、训练或CUDA内核，因此没有压缩率/设备性能声明。

```sh
sh systems_practice/paper/2026-10-26/01-minima/run.sh
```

Python3.9.6标准库、固定4个logit/标量V，无安装/下载。独立输入包含±1000，比较完整softmax、稳定合并、错误的局部平均；9组切分/整体平移检查和空分区拒绝。实际[结果](results/cpu.txt)：参考与合并2.4621171572600096，简单平均−16.079527207670044，9例最大误差0。它只检验FP64数学边界，不能证明压缩缓存的数值或模型任务精度。

## 复现路线与故障分析

完整复现难：先取得作者runtime/codec、固定模型和所有profile manifest，再构造相同request和分层字节统计，最后在对应硬件比较质量、路由、dense shadow、速度。缺源码许可和配置绑定是当前首要障碍；此任务未下载模型。若迁移Thor，需独立sm_110实现/构建、正确性基线和ncu/ISA验收，不能移用作者RTX成绩。

独立排障一：局部输出直接平均→低logit分区贡献异常→用本例对照全局softmax→保存m/l后合并，多出少量统计量。排障二：压缩率好但峰值不降→dense shadow/工作区仍驻留→统计真实分配与阶段峰值→释放时要等待设备完成，增加生命周期管理成本。以上是本例工程推论，不是假称已遇到的作者生产事故。
