# When Compression Scores Cannot Decide: Information Boundaries for Group-Robust LLM Pruning

Andrew Zhang；[arXiv:2608.02940v2](https://arxiv.org/abs/2608.02940v2)，首次2026-08-03、v2日期2026-08-06，预印本，CC BY4.0。2026-09-30实际读[全文](https://arxiv.org/html/2608.02940v2)§2–3（含Table1、分组反例、slack公式）、§4–6、§7.1–7.2与Appendix C最终选择/评估分离部分。作者实现链接未从正文/精确标题GitHub检索中核实，不把arXiv的Report GitHub Issue链接当作者代码。

## 问题、关键公式与作者结论

平均局部损伤相同不代表最差组相同。`(4,0,0,0)`与`(1,1,1,1)`均值均为1、最大值却为4/1。令当前风险r、slack `s_g=max(r)-r_g`，下一步最大风险变化精确为`max_g(δ_g-s_g)`；只盯当前最差组会漏掉组切换。

论文§5.2中一个split-half可靠性0.906的二阶代理预测16.1%/16.0%改善，完整端点却相对两控制退化6.0%/7.7%。这是其冻结剪枝实验的代理失配，不证明二阶方法普遍无用；完整模型候选与独立分组评估仍要付出计算成本。[原文](https://arxiv.org/html/2608.02940v2#S5)。

## 复现路线与工程故障

难度中到难：数学反例易复现，完整LLM评估需要确切代码/数据分组、冻结checkpoint、多候选预算和独立endpoint测试；作者仓库与依赖版本未核实，保留待补。先核对作者实现和许可证，使用本地已有小模型做同预算mask对照，再扩大；不自动下载论文模型或语料。小例秒内完成仅为本地估计。

故障链一：整体PPL良好但罕见输入坏→看分组端点而非只看校准均值→确保分组来自部署合同，不在测试结果后挑组。故障链二：单步最差组改善、多轮最终退化→记录每一步风险向量/slack和候选变化→重新评估完整状态，不能把一次局部证据当多步保证。工程候选最终应同时比较模型质量、真实存储和设备时延。

迁移验收：声明目标指标（KL、NLL或任务分数不能混用），固定稀疏预算、完整mask、校准/选择/评估分离；同组统计和置信范围；板端真实shape/稀疏后端性能另测。追问：1. 均值丢失什么信息？2. 为什么各单元max之和不是整体max？3. slack为何需要完整向量？4. 为什么选择集改善不能算测试集改善？
