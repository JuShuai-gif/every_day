# Quantization-Triggered Backdoors in Language Models: Cross-Quantizer Transferability and the Validation–Deployment Gap

2026-10-07阅读；Jacopo Dardini、Claudio Stanzione、Giordano Colò、Giuseppe Fenza。[arXiv2608.27512v1](https://arxiv.org/abs/2608.27512)，首发/版本2026-08-27，41天。arXiv作者备注“Accepted at ARES 2026”，会议出版记录未独立核实。实际读[全文HTML](https://arxiv.org/html/2608.27512v1)§3.2–3.4、§4.1/4.2表2、§6.4；不是只读摘要。

## 问题与防御性收获

发布前仅验证全精度模型不足以证明量化后行为一致。映射Q是多对一：同量化格子的多个浮点权重可能给出不同输出；缩小一般误差也未必守住决策边界。关键工程要求是将最终导出格式、后端和运行配置纳入相同的成对回归。

作者表2的M2M100-1.2B、英译乌合成测试中，修复后FP16的指定语义翻转率为0，NF4为85.02%。这是作者特定实验的指标，既非普遍攻击成功率，也非真实部署事故；合成数据、模型规模与量化器选择限制外推。§4.1明确设备配置表不是硬件基准，因此本期没有用它证明任何Jetson速度。

读到的核心几何是量化等价类 `{w':Q(w')=Q(w)}`。本期仅实现防御性阈值验证，不训练后门、不构建恶意checkpoint。若输出变化上界e严格小于原输出离阈值距离，当前阈值判断保持不变；边界上的等号不能获得这种保证。实际多类模型需检查相关logit margin及完整行为指标。

## 作者实现与复现难度

全文§6.4明确不公开完整训练产物、修复模型和完整数据；未找到作者官方实现仓库，source记录为未读代码。论文是方法一手资料，不能把自己的例子写成作者API。完整复现难：缺少这些产物和确切环境，需自行定义数据与训练过程；本次不执行该攻击复现。

可做的最小验证路线：对用户已有合法本地模型保存全精度参考输出、固定校准/量化格式、重载最终产物，再比较任务指标和边界样本。需要对应框架/量化后端；PyTorch与Thor环境目前缺失，不下载模型。不能只用总体BLEU/均值误差代替关键子集回归，也不承诺检测覆盖所有潜在后门。

## 工业故障与迁移验收

只在FP16评估→导出后关键样本变号→固定输入成对比较重载产物→把量化格式/scale/后端纳入版本与回归→验收失败阻止主课Registry发布。

平均误差低却出现边界错误→决策间距接近量化扰动→分层记录margin和阈值变化→增加边界子集验收，不能用总体平均覆盖→分布变化时重新评估，保留原结果。

量化scale重新估计会改变格子；本文小例冻结scale，仅解释局部数学，不证明动态量化器下相同等价类。验收：记录所有格式/校准/后端版本；评估集与校准分离；逐项检查关键业务输出；GPU/存储/E2E单独测。追问：同一个量化码为何不能证明原函数相同？绝对误差怎样结合margin？冻结和动态scale怎样改变等价类？为何必须验证重载后的最终产物？
