# ARM 就业能力与操作系统衔接

2026-09-28：用户要求把就业导向加入生成要求，并询问 xv6-public 和 VivekPublicRepo。本文是后续选题与证据要求；不是新交付课程，也不表示已经完成操作系统学习或板端项目。主规范见[生成要求](../PRACTICE_SPEC.md)。

## 主线与优先级

以嵌入式 Linux / 边缘 AI 推理工程为主线，再深入 ARM CPU 算子与性能优化。按以下顺序积累能力：

1. C/C++ 工程、Linux 调试和构建：所有权、异常/退出、并发、CMake、交叉编译、动态库、GDB/core dump、Sanitizer。
2. 推理正确性与稳定性：模型转换、输入预处理、shape/stride/dtype、量化误差、缓冲区复用、超时恢复和连续运行。
3. 性能分析：预热、P50/P95、吞吐、CPU计算/复制/排队/同步/设备时间分别测量；根据证据定位瓶颈。
4. ARM 具体优化：访存、缓存/布局、NEON、尾部与数值误差、寄存器依赖、多线程；汇编帮助解释热点。

不同就业方向需要不同深度：MCU/RTOS偏外设和实时性，BSP/驱动偏启动/设备树/板级调试，边缘推理偏部署与流水线，算子岗位偏体系结构和测量。当前路线优先后两项并补齐 Linux 工程基础，不要求所有方向同时精通。

近期职位样本提供技能组合依据：[乐鑫 Linux 嵌入式工程师](https://www.espressif.com/zh-hans/job-detail/9381)强调驱动、U-Boot、设备树和系统集成；[Arm 性能分析工程师](https://careers.arm.com/en/job/shanghai/staff-application-engineer-performance-analysis/33099/100749196192)强调 Linux 工具、CPU/缓存/内存与跨层排障。2026-09-28阅读；不是职位数量或薪资统计，资深职位要求不是入门门槛。

每课交付一句岗位能力、一个具体板端问题和可检查的证据。主课原有结构承载“问题→测量→根因→修改→正确性→性能与限制”；一天仍只有一个20–30分钟必做编码练习和一个无答案自测。

## 操作系统为什么值得学

为解释生产问题补机制：进程为什么阻塞，内存为什么第一次访问慢，线程加多为什么尾延迟恶化，通知为什么丢失，设备忙完之前为何不能复用缓冲区。不要把系统调用耗时、设备内核耗时和请求耗时合在一起。

建议学习顺序如下。它是按前置组织的参考路线，不是额外每日栏目；完整机制需要跨多次相关主课/综合阶段展开。

| 顺序 | OS 机制 | 对应工程问题 | Linux/板端应保留的证据 |
| --- | --- | --- | --- |
| 1 | 用户态/内核态、系统调用、进程/线程与文件描述符 | 程序调用服务、子进程退出、句柄泄漏 | 小C/C++调用链、错误返回、进程/FD状态 |
| 2 | 地址空间、页表、缺页、按需分配、映射生命周期 | 大模型加载、首次触页、内存占用 | 地址/页大小/驻留及缺页记录；与Cache区别 |
| 3 | 锁、等待条件、睡眠与唤醒 | 队列空/满、背压、丢失唤醒、关闭竞争 | 可复现时序、谓词检查、正确性/竞争诊断 |
| 4 | 调度、上下文切换与亲和性 | CPU不忙但请求慢、线程过量、大小核差异 | 墙钟/线程CPU时间、等待时间与调度轨迹 |
| 5 | 管道/IPC、I/O、阻塞与就绪通知 | 摄像头/网络输入、服务队列、慢消费者 | syscall/队列时序、吞吐和尾延迟 |
| 6 | 文件/缓存、一致性、设备与DMA边界 | 模型加载、日志可靠性、CPU–加速器缓冲区 | 针对具体Linux/驱动版本的合同与故障证据 |

Linux工具按问题选择，例如GDB/core/strace/perf。缺少Linux环境时只交付目标命令和待验状态；Mac上的相近现象不标成Linux结果。DMA、驱动、futex和生产调度策略需另读Linux/SDK一手资料，不能用xv6演示替代。

## xv6：适合学机制，选对版本

用户链接的[xv6-public](https://github.com/mit-pdos/xv6-public)是**x86教学版**。其README明确停止维护，工作转向[xv6-riscv](https://github.com/mit-pdos/xv6-riscv)。新增阅读以RISC-V版和[MIT 6.1810](https://pdos.csail.mit.edu/6.1810/)同一学年/实验版本材料为主；旧版可作历史对照。

本次实际阅读：

- xv6-public：master README 的维护说明、架构与构建前提；未完成其内核实现审查。
- xv6-riscv：riscv分支 README、LICENSE，以及 [kernel/pipe.c](https://github.com/mit-pdos/xv6-riscv/blob/riscv/kernel/pipe.c) 的 `pipewrite/piperead/pipeclose`；看到满/空条件、关闭状态和等待唤醒调用。
- xv6-riscv：[kernel/proc.c](https://github.com/mit-pdos/xv6-riscv/blob/riscv/kernel/proc.c) 的 `scheduler/sched/sleep_prepare/sleep/wakeup`。当前读取版本使用先登记等待通道再睡眠的接口；不能照旧教材凭记忆写成另一种参数签名。

本次读取日期2026-09-28，精确commit未解析；本地git访问DNS失败，仅网页读取。RISC-V版许可证为MIT许可文本。上述链接是分支链接，不是假称的永久链接；正式源码实验必须固定实际读取的版本，并重新核对教材接口。本次未克隆、编译或在QEMU运行。详见[来源与失败记录](../results/career-os-20260928/sources.json)。

学习时先看“进程如何睡眠与唤醒”等小调用链，再配相应章节和小实验。xv6可建立机制理解；Linux的调度、线程模型、内存管理和驱动复杂度需要另外学习。RISC-V的寄存器、异常入口、页表和内存序不是AArch64规格。RISC-V工具链和QEMU是该教学实验的独立运行环境，不改变Thor SM110的CUDA目标，也不自动安装任何依赖。
