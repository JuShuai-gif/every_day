# 每日 OS：从 xv6 到边缘推理部署

2026-09-28 用户明确要求新增独立OS主题并每日讲几个知识点。采用每天一节、两个紧密相关小主题，估计阅读/观察10–15分钟。随既有北京时间08:30任务运行，不新建重复定时任务。第一轮28节、56个主题；不是28天内必然完成的承诺，缺项先补，学习游标独立。

## 来源与边界

主读[MIT xv6-riscv](https://github.com/mit-pdos/xv6-riscv)与同版本课程；用户最初的[xv6-public](https://github.com/mit-pdos/xv6-public)是停止维护的x86历史版。以真实文件/调用链拆分，而非仅整理概念。xv6是教学内核，不是Linux、ARM内核或加速器SDK；RISC-V的异常/页表/指令不能当成AArch64结论。

每期先查课程表与进度，实际读取具体源码再讲解；清单中的source_candidates只表示选题线索，不表示已读或该版本一定存在该机制。尤其COW属于需核实的课程扩展，不假称上游已实现；最后10节是明确的Linux/边缘迁移专题，必须另读Linux/SDK原始资料。可使用经过核实的本地源码缓存，记录commit和工作区状态；获取失败可通过网页读实现，并记录版本固定/克隆/运行边界。

## 每日固定交付

目录为 `systems_practice/os/YYYY-MM-DD/`，按[模板](LESSON_TEMPLATE.md)提供：两个主题的原理、源码文件/符号/调用链、一个已写好的最小C/C++例子或观察入口、与Linux/ARM的差异、边缘场景与故障信号、命令/真实输出/验证边界、下一节。默认不增加用户必做编码作业或自测；主课仍保留唯一20–30分钟编码练习和一个无答案自测。OS例子不套主课十二标题或450–700字限制。

xv6内核原生代码使用C和必要汇编，遵循内核接口；宿主/Linux例子默认C++17、RAII、错误检查与中文关键注释。不要为了RAII把xv6内核改成C++。需要修改xv6时交付针对已核实版本的完整补丁/程序和构建运行命令；不能仅留TODO或伪造QEMU结果。没有工具链时仍可交付真实源码讲解、宿主机制观察以及完整目标命令，但逐项标明未验证。

source.json记录仓库、commit/tag或读取日期/分支、文件/符号、调用链、许可证、关系（原始/改编/独立启发）、失败尝试。verification.json分别记录source_read、version_pinned、host_compiled/run、xv6_compiled/qemu_run、linux_run、target_board_verified与性能范围。results保存真实结果，build/.tmp保持忽略；不安装依赖，不下载大型模型，不复制整仓入Git。
