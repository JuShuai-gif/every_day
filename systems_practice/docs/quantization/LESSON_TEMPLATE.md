# 每日量化栏目模板

这是交付模板，不是已完成的课程。每期放在独立目录 `systems_practice/quantization/YYYY-MM-DD/METHOD/`，所有占位说明必须替换为真实内容；缺失证据明确标记未验证。主 README 保持既有结构并链接此栏目。

## 方法与应用场景

写明日期、方法、具体设计点及原项目解决的问题。解释何时选择它、与 absmax 或上一方法的差别和代价。列出形状、布局、位宽/格式、scale 粒度、舍入/零点/累加精度。

## 原仓库与实际读过的实现

填写仓库 URL、commit、日期、许可证和 source.json 路径；至少给出算法核心与用户入口的文件/符号永久链接。用短调用链连接“用户传入什么 → 内部统计/优化/打包 → 返回什么 → 后端怎样计算”。区分原样调用、改编与独立教学实现。路径迁移、缺文件和未阅读处如实记录。

## 如何接入我的代码

交付完整 example.py/.cpp 和 run.sh，配中文关键注释，必须包含：

1. 实际核验的环境/包版本、工作目录、固定 commit 的准备命令；安装命令可以说明，但不自动安装。
2. 小 Linear/GEMM、随机小模型或本地模型输入；无模型下载也能观察核心机制。依赖不足写明先决条件和目标设备命令。
3. 来自已读源码的真实 import/API/CLI 与必要参数；解释 bits、group size、alpha、damping、threshold 等当次实际存在的参数，不能硬套所有方法。
4. 校准或训练样本的具体构造、冻结/转换/导出/推理步骤，以及接入已有模型的替换位置。不同数据分区不得混用。
5. 输出/保存文件的位置与含义；从导出格式到实际 GEMM/注意力 kernel 的支持边界。
6. 一条可复制运行命令和明确验收检查。解释错误输出意味着什么，不能只列安装命令。

不支持小 Linear 的上游接口使用其支持的最小规模，不臆造接口。独立数学示例另设文件并标明来源关系；它不能替代“原仓库怎样用”。

## 量化前后比较

对同一输入比较参考与该方法；根据对象选 GEMM、注意力/解码或训练更新。列出真实误差、饱和、权重/scale/索引等字节数、预处理/kernel/端到端计时边界。数值来自 results/ 原始输出；缺设备则表中填未验证，不填估计加速比。QAT 必须有实际参数更新。写出至少一个边界或失败案例。

## Thor SM110 与优化

原项目是否支持 Thor、依赖如何构建、执行的是 fake quant/SIMT/Tensor Core 哪条路径，都需证据。涉及 GPU kernel 时链接正确性基线与最终优化版、ncu 使用教程、真实 PTX/SASS 导出命令、热点指令/依赖分析和架构对照。其他架构仅理论比较。缺目标设备/工具链时标记优化收益、编译和执行未验证。

## 验证与待补

verification.json 至少记录 method、date、repository、commit、source_record、source_fetched、source_read、example_delivered、cpu_example_run、thor_verified、read_symbols、evidence、blockers。布尔状态必须有文件/函数或日志证据；缺硬件不标成功。source.json 保留获取时的事实，不把下载脚本的初始 false 当作之后阅读/运行的状态。

拉取失败时附原始日志与重试命令，原项目用法留待补。源码已读取、完整示例已提供但依赖缺失时，可记录已交付/未运行。同步更新独立索引、progress.json 的 history/backlog 和主索引的栏目链接。保持主练习唯一无答案自测，不新增第二个强制作业。
