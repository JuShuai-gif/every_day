# 2026-10-19 CPU 体系结构：转置分块与 stride 合同

## 工业场景

机器人视觉编码器的CPU适配层需要把FP32特征 `[M,N]` 物化为 `[N,M]`。典型1024×1024，输入/输出可带7元素行尾间隙；预算是每请求一次转换、内存有界、不污染相邻ROI。这里处理两块独立拥有的vector，拒绝原地/同对象转置；不含相机、GPU、NPU、网络或推理。目标是解释为何同样8MN逻辑字节量，stride与访问次序会让CPU时间相差很大。

## 概念回顾

矩阵转置只改变元素位置，却同时考验缓存局部性和地址合同。行主序输入中相邻列连续，按行读取有利于利用一次缓存行填充；输出的同一批元素却落在不同目标行。若目标行跨度过大，尚未填满的缓存行可能在下一次更新前被替换。写分配、缓存组映射、预取与地址翻译都会影响代价，因此逻辑上每个元素读写各一次，并不意味着内存总线只传输两次元素大小，也不能从一次耗时突变直接反推出缓存容量或相联度。

分块把访问限制在局部矩形，使短时间内反复触及的目标行数下降。块内仍按输入行遍历，块外依次移动到下一个区域。它没有减少数学工作量，也没有减少输出元素数量；收益假设是提高缓存行的有效复用。块太小会增加循环控制，块太大可能重新超过缓存或翻译结构的有效工作范围。线程、编译器自动向量化、频率和预热也会影响结果，所以三十二只是本课候选参数，不是任意CPU的最优常量。小矩阵完全驻留时，额外循环反而可能拖慢。

第二个机制是stride与所有权。逻辑列数描述有效元素，stride描述相邻两行起点的距离，两者相等只是连续布局的特例。最后一行之后不一定分配完整padding，尾块必须取剩余行列的最小值。计算容量前先检查乘加溢出，访问前验证输出形状，并拒绝共享对象，否则性能修改可能掩盖越界或读写覆盖。RAII容器管理分配和异常退出，但不会自动证明索引正确。本课用整数可精确表示的浮点输入逐元素核对，同时检查行内padding不变。先获得这些正确性证据，再分别测预分配循环与含分配调用，才能判断分块是否值得进入实际推理链路。

## 性能分析

同一输入、同一-O3、三次预热、11批交替先后顺序；小shape每批100次，大shape5次。日志P50/P95是**批均值**分位数，不是请求尾延迟。循环路径排除分配；allocation路径包括vector初始化、转置与释放，仍不是推理E2E。校验不计时；编译器屏障防止重复写消除，普通循环可能自动向量化。tile32的两块逻辑数据约8KiB，但缓存行分布/相联度不能由此断言。

Linux定位方法（Mac未运行）：先 `perf list` 核对PMU事件；`perf stat -r 5 -e cycles,instructions,cache-references,cache-misses -- build/release/practice --bench` 只是全程序累计含校验/两版，不能作为单kernel证据。用 `perf record -g -- build/release/practice --bench` 和 `perf report` 定位`plain/blocked`，再 `perf annotate` 关联加载/存储。若要归因单版本，先给基准加单版本过滤入口，并单独计数；无事件权限就记录不可用。需同时核对CPU迁移、温度、页大小与频率，再判断冲突失效、TLB或写分配假设。

## 实际运行结果

Mac arm64、Apple clang21、Release与ASan/UBSan通过。转置循环批均值P50（µs）：

| shape / padding | plain | tile32 |
| --- | ---: | ---: |
| 17×19 / 0 | 0.10583 | 0.12625 |
| 1024×1024 / 0 | 3413.75 | 386.467 |
| 1024×1024 / 7 | 327.533 | 286.925 |
| 1023×769 / 7 | 247.633 | 217.117 |

1024²连续布局含分配调用为3609.07/475.417µs。保留小shape退化；padding仅改变步长，plain时间已大幅变化，说明不能笼统承诺分块固定收益。未采PMU，缓存冲突只是假设；未测RK3588/Thor CPU、GPU/NPU、长期热稳定和推理E2E。

## 工程注意事项

`Matrix`容量以最后有效元素为界，padding不是有效像素。输入非有限浮点本课不产生，转置不做算术，实际服务可按字节比对NaN；此例的`==` oracle仅用于有限值。最大工作集由调用方限制；size_t溢出检查不等于满足设备内存预算。实际ROI借用接口还应增加长度与重叠区间验证，本课独立所有权接口不接收裸外部buffer。

今天没有CUDA kernel，GPU对照游标保持Hopper，下次轮到Ada；CUDA执行目标仍仅Thor sm_110，不从CPU结果推断GPU收益。量化后端审计与工具链边界见量化栏目。
