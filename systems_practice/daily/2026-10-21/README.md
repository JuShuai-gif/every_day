# 2026-10-21 ARM SIMD / NEON：INT8量化的舍入与饱和窄化

## 工业场景

机器人视觉编码器将连续FP32激活转成对称INT8，为CPU后处理或后续设备提交准备输入。代表输入是1×1024×1024个float，输出同元素数的signed byte；此练习只测CPU转换，不包含相机、排队、传输和推理。目标是逐元素一致、无越界、资源由vector管理。验收以数值合同为先，再判断是否采用SIMD；无硬实时保证。

实际读取[ncnn](https://github.com/Tencent/ncnn) master（2026-10-21，HEAD查询为7e36d25cb153092ba87a60530455c7376fedf452）：`src/layer/arm/quantize_arm.cpp` 的 `Quantize_arm::forward → quantize → float2int8` 与 `arm_usability.h` 的两个重载。BSD-3-Clause。原场景含Mat packing、分通道scale、线程与FP16/BF16分派；本课是**受其机制启发的独立实现**，保留浮点缩放、舍入和窄化，缩为单scale、连续数组，并额外定义非有限输入合同；未把上游异常值行为称为本课合同。来源细节见[source.json](source.json)。

## 概念回顾

把浮点张量装进八位数组，首先要确定数值语义，再决定如何并行。这里输入是连续浮点数和正有限逆尺度，先在单精度中相乘，随后把非数值映射为零，把正负无穷和越界结果钳位到正负一百二十七，最后按最近整数、恰好一半时远离零的规则舍入。这个顺序既避免浮点转整数超出表示范围，也让标量与向量面对同一个数学合同。直接强制类型转换采用向零截断，不能替代这里的舍入；最近偶数又是另一条合同，三者在半整数附近会产生可观测差异。

主机制是向量浮点转整数，耦合机制是饱和窄化与真实访问边界。每轮加载两个四通道向量，分别完成乘法、非数值屏蔽、上下限夹紧和三十二位整数转换，再依次收窄为十六位与八位，最后写出八个结果。饱和窄化能够约束整数范围，却不能自动修复前面选错的舍入方式。对称量化刻意不使用负一百二十八，因此范围选择也必须与消费端一致。非数值屏蔽使用自身相等比较，编译时若承诺没有非数值，优化器可能删去这段保护，所以本课不启用快速数学选项。

数组尾部不足八个元素时只访问剩余合法区间，不能因为分配器通常多给空间就继续读取整向量。输入偏移可以不满足十六字节对齐，但必须仍指向有效浮点对象；这与可任意按字节错位不是同一件事。资源寿命由拥有数组的容器覆盖整个调用，输入输出约定不重叠。性能比较保留相同数据、相同尺度、相同验证与采样方法；标量基线关闭循环自动向量化，候选尾部仍允许编译器优化。真实指令证明编译器采用了哪条路径，耗时和硬件计数器才能继续检验瓶颈，不能由向量宽度直接推断加速比。

## 知识图谱

`FP32乘法 → NaN屏蔽 → ±127夹紧 → FCVTAS → SQXTN两级窄化 → byte存储`。

| 耦合点 | 代码与前置 | 容易混淆 |
| --- | --- | --- |
| 舍入与窄化 | `convert/one`；先有限范围后转换 | 饱和不修复舍入；INT8不等于FP8 |
| 向量访问与寿命 | `neon`的n-i>=8、尾部、vector | 有padding不等于允许越过逻辑长度 |
| 优化证据与计量域 | `measure`、真实A64汇编 | CPU批均值不等于单请求P95或设备耗时 |

## 正确性验证

12种长度×3偏移×3尺度×13边缘位置=1404组合，含零长度、奇尾、半整数及相邻float、最大有限值乘法溢出、±Inf、NaN、signed zero。输出两侧哨兵保持。oracle在FP32乘法之后用double的floor/ceil独立实现舍入。4种非法scale拒绝；显式展示0.5的截断反例。Release和ASan/UBSan均通过；这不能证明任意调用者传入无效指针也安全。

## 性能分析

每个shape预热8次，11批；每批重复 `max(4,1048576/n)`，报告批均值微秒的P50/P95。两实现交替先后，数组分配和校验在计时外，编译器memory clobber防止重复写被删，不刷新CPU cache。逻辑读写量5N字节，N=1048576为5MiB；它不是DRAM实测流量。除算术之外还受热缓存、频率和系统调度影响。

实际主体汇编 `ldp q3,q4 → fmul.4s → fcmeq.4s/and.16b → fmin/fmax → fcvtas.4s → sqxtn/sqxtn2 → str d3`。FCVTAS把4个float按远离零规则转换，SQXTN饱和收窄，STR D写8B。源码的`vcombine`可折叠进SQXTN2。尾部被编译器自动向量化为FRINTA+FCVTZS等；n=7的收益不能归功于根本没有执行的8元素循环。未采PMU，因此没有“访存受限”或周期数的实测结论。详见ARM26的perf分析路径。

## 工程注意事项

禁用fast-math；FP32乘法和NaN策略为接口合同，而不是训练量化算法。要接真实模型必须同步scale、zero point、舍入及范围，不能把本文固定scale当AWQ/LLM.int8。四种W/A位宽的矩阵乘仍由独立量化GEMM方向承担。

## 工业故障与面试追问

1. **半整数通道偏差**：边界激活出现稳定±1差异→怀疑截断或ties-to-even→用±0.5、±126.5及nextafter复现→固定同一舍入合同；代价是不能随意换廉价指令。
2. **NaN仅优化版变成随机大值**：启用fast-math后保护消失→查看FCMEQ并跑NaN输入→去掉不成立的有限数承诺或在入口拒绝；增加一次入口检查或掩码成本。
3. **奇尾偶发越界**：n=9时整向量多读→ASan和紧长度分配→循环判剩余量、独立尾部；牺牲部分小shape吞吐。

面试追问：①截断、最近偶数、远离零差在哪？②为什么夹紧应先于整数转换？③SQXTN能替代NaN策略吗？④未对齐load与越界load有何区别？⑤为什么n=7的性能不能证明主体循环收益？⑥如何用PMU和E2E证明是否值得上线？
